# Auto Dark Mode（自动深色模式）

一个轻量级的 Windows 应用，按时间自动把系统在**深色 / 浅色模式**之间切换——可按固定时间计划，也可根据你的位置计算真实日出/日落。

基于 **Go + Wails v2** 与纯 **Vanilla JS** 前端（无 JS 框架，运行时不需要 Node）。唯一运行时依赖是 WebView2 运行时（Windows 10/11 自带）。

> 📖 完整的设计、功能与使用文档见 [`docs/DESIGN.md`](docs/DESIGN.md)（架构、功能说明、使用指南、配置字段、构建发布、设计决策与已知限制）。本文为英文版 [README.md](README.md) 的中文对照版，两份内容相互对应。

## 功能特性

- **系统级切换** — 改写 `HKCU\...\Themes\Personalize` 中的 `AppsUseLightTheme` / `SystemUsesLightTheme`，系统外壳与大多数应用即时切换。
- **两种模式**（在设置中选择其一）：
  - *日出/日落*：根据你的坐标计算每日日出与日落时间。
  - *固定时间*：深色从某时刻持续到另一时刻。
- **位置解析**，按优先级：
  1. **自动（GPS → IP）**：先用 Windows 定位 API，失败回退 IP 归属地。
  2. **手动坐标**：自行输入经纬度。
  3. **城市选择器**：从内置主要城市表中选择（无需网络）。
- **系统托盘图标** — 打开设置 / 强制深色 / 强制浅色 / 自动 / 退出。
- **开机自启**（可选，在设置中开关）。
- **关闭收起到托盘** — 点窗口 X 收起到托盘而非退出（默认开启；用托盘"退出"彻底退出）。
- **中英双语（中文 / English）** — 跟随系统语言，可手动覆盖；覆盖设置界面、托盘菜单与状态消息。
- **设置界面跟随系统主题** — 设置窗口与它所驱动的深/浅色保持一致。
- 设置窗口（Go 后端 + Vanilla JS UI），配置持久化为 JSON。

应用内调度器每 30 秒检查一次时钟，因此即使经历睡眠/唤醒，主题也会在半分钟内跟上；唤醒后的主题应用会延迟到 Shell 就绪后执行（约 8 秒），避免任务栏/资源管理器错过切换广播而残留旧主题；若主题跨睡眠真实变化，约 45 秒后还有一次仅针对任务栏侧的兜底翻转（详见下方"已知问题（已修复）"）。

## 已知问题（已修复）

### 睡眠唤醒后，任务栏与资源管理器内容区不跟随主题切换

**状态**：✅ 已修复（找到了真正的根因：唤醒探测从未生效——见下文）。

**历史现象（复现步骤）**

1. 应用处于**自动模式**（启用自动切换，主题由时段决定）；
2. 在**深色时段**让电脑进入睡眠/休眠（入睡时任务栏为深色）；
3. 在**浅色时段**唤醒电脑（按计划此时应为浅色）；
4. 修复前的实际表现：
   - ✅ 第三方应用正常变为浅色；
   - ✅ 文件资源管理器的**菜单栏/标题栏**正常变为浅色；
   - ❌ **Windows 任务栏**保持深色；
   - ❌ 文件资源管理器的**文件列表内容区**保持深色。

**实测行为（最初修复方案的关键线索）**

- 唤醒后在托盘点"**强制浅色**"**无法**让任务栏变浅色；
- 必须先点"**强制深色**"、再点"**强制浅色**"——即让注册表主题值经历一次真实的 深→浅 翻转——才能恢复正常；
- 该现象说明：Shell 能响应"注册表值真实变化"的广播，但对"值未变化的重复广播"不做重绘。

**真正的根因（在几轮"差一点修好"之后找到）**

此前整套"等 Shell 就绪后再一次性应用"的设计**从未真正运行过**：它依赖的唤醒探测**从未触发**。

- 探测逻辑拿墙钟与 `GetTickCount64` 对比，前提假设是"该计数器在睡眠期间不走"。而 MSDN 明确写着相反的内容：tick 计数是**有偏的（biased）——包含睡眠/休眠时间**（这正是它与 `QueryUnbiasedInterruptTime` 的区别所在）。于是墙钟差 ≈ 计数差 → 误判为"没睡过" → 唤醒后第一个调度 tick 走普通路径**立即**写主题并广播，此时 Shell 尚未恢复完成——任务栏错过唯一一次真实跳变的广播；而它只对"真实变化"重绘，从此永久卡死。
- 还有两个帮凶：① 入睡事件（away-mode 进入方向的通知）也会武装那 8 秒延迟应用——有偏定时器在睡眠期间"到期"后会在机器唤醒的**瞬间**触发（Windows 文档明确描述了这一行为），即使电源事件路径正常，延迟也被架空；② `SendMessageTimeout` 带 `SMTO_ABORTIFHUNG` 时对挂起窗口会**静默丢弃**消息，跳变广播一旦被丢就再也不会补发。

**修复方案（已实现，见 `theme.go` / `app.go` / `tray.go`）**

1. **唤醒探测真正生效**：调度器改用 `QueryUnbiasedInterruptTime` 与墙钟对比——该计数器只在机器实际运行时前进（不含睡眠/休眠），因此唤醒能被可靠检出（即使收不到任何 `WM_POWERBROADCAST`），随后**唤醒 8 秒后**一次性应用目标主题，此时 Shell 能听到广播，失步状态根本不会形成。**且唤醒应用待决期间，调度器 tick 一律让行**：Go 中睡眠期间错过的 ticker deadline 会在唤醒瞬间背靠背连发——没有这道门禁时，第二个 tick 因墙钟差极小被误判为"没睡过"，会在唤醒 +0.5 秒偷跑写入：偷走真实跳变、架空 8 秒延迟、连带解除 45 秒安全网（2026-09 由诊断日志实锤的根因）；
2. **延迟防睡眠穿透**：入睡方向的事件不再武装任何延迟应用（away-mode 只在"离开"即唤醒方向才触发），且延迟等待本身按实际运行时间计——若等待中途机器入睡，唤醒后会把剩余时间重新等满；
3. **可靠的投递**：`applyTheme` 采用经典的 写入 → `RefreshImmersiveColorPolicyState` → 广播 顺序，并把通知**定向投递给任务栏窗口**（主任务栏**和**副显示器的任务栏）——先同步发送，再补一条排队式 `PostMessage`，广播时仍处于挂起状态的任务栏稍后也能收到；
4. **像素门禁的任务栏侧兜底**：若唤醒后的延迟应用发生了真实跳变（主题跨睡眠变化——这是任务栏唯一可能"卡死且无人能救"的场景），约 **45 秒后**执行一次兜底愈合——**先采样任务栏真实像素**（9×3 网格，`BitBlt` 读取；`GetPixel` 在新 Windows 构建已不再导出）：读数高置信度已是目标色则**直接跳过翻转（零闪动）**；只有读数模糊或确实卡住才执行翻转，且翻转只动 `SystemUsesLightTheme`（任务栏跟随的那一侧），**所有应用不会闪屏**；翻转后 +2s/+5s 还有投递阶梯重发定向通知，确保"翻回"那一下不被漏掉；
5. **更温和的手动愈合**：托盘"强制深色/浅色/自动"的单击矫正同样只翻系统侧键——手动修复卡死任务栏时，桌面应用不再整屏闪黑。

**代价与说明**：跨主题唤醒后主题约延迟 8 秒生效。像素读数高置信度时安全网**完全跳过翻转——零闪动**；读数模糊（或采样不可用）时任务栏可能短暂切换一个来回（约 3 秒），随后数秒内**自动**纠正、绝不需手动。托盘单击"强制浅色/深色"仍是最后手段。

**历史排查记录**（留存供参考）：前几轮修复在一个从未生效的唤醒探测之上搭了越来越复杂的愈合机制，因此症状始终复现（早期的自动翻转还带来了整屏深↔浅闪动）。决定性的一步是去核对计数器的**文档行为**而非想当然的假设。

## 构建与发布

版本号遵循 SemVer，**每次产出新 exe 前**必须运行 `build\bump-version.ps1 -Patch|-Minor|-Major` 完成升位与全量同步——升位规则、同步文件清单与版本历史见 [`docs/VERSIONING.md`](docs/VERSIONING.md)。

支持两种发布形式：

### 1. 便携版单 EXE

```bash
wails build
```

生成独立的 `build/bin/autodark.exe`——复制到任何地方即可运行。不安装任何东西，不修改注册表/开始菜单。使用系统 WebView2 运行时（Windows 10/11 自带），无需额外安装。

### 2. 引导式安装包（NSIS）

```bash
wails build -nsis
```

生成 `build/bin/autodark-amd64-installer.exe`，一个引导用户操作的 Windows 安装向导：

- 启动时可选择安装界面语言（**English / 简体中文**；每次运行——包括重新安装——都会弹出选择框，选择会记住供卸载时沿用）
- 欢迎 → 安装目录 → 安装中 → 完成 各页
- **安装时若检测到应用正在运行，可选择结束进程并继续安装**（静默安装时自动结束）
- 安装到 Program Files，创建**开始菜单**与**桌面**快捷方式
- 缺失时检查并安装 WebView2 运行时
- 完成页提供"安装后运行 Auto Dark Mode"选项
- 带完整的**卸载程序**（卸载前自动结束运行中的实例）

#### 安装包构建前提

构建安装包需要 PATH 上有 NSIS（`makensis`）。用 [`scoop`](https://scoop.sh) 安装：

```bash
scoop install nsis
```

### 一次构建全部

```bash
build.bat            # 便携 exe + NSIS 安装包
build.bat portable   # 仅便携 exe
build.bat installer  # 仅 NSIS 安装包
```

### 开发热重载

```bash
wails dev
```

## 配置

持久化于 `%APPDATA%\AutoDarkMode\config.json`。首次运行以**日出/日落**模式 + **自动**定位启动自动切换。

轻量诊断日志轮转于 `%APPDATA%\AutoDarkMode\app.log`（1MB × 3 代），记录唤醒探测、注册表写入、广播、翻转与像素门禁决策——2026-09 的根因分析正是靠它完成的。**完整的事件目录、健康唤醒基准时间线与"症状→签名"排查手册见 [`docs/LOGGING.md`](docs/LOGGING.md)——同类问题再次出现时先读它。**

## 说明

- GPS 定位需要 Windows 位置权限（首次使用系统可能弹窗）。不可用时静默回退 IP 归属地，再回退手动/城市。
- IP 归属地使用 `ip-api.com`（免密钥，非商业用途）。
- 日出日落使用 NOAA 太阳算法；已用纽约市真实坐标的已知日出日落值做过校验（见 `solar_test.go`）。
