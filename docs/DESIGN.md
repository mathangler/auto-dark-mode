# Auto Dark Mode —— 设计、功能与使用文档

> 版本：1.3.0 ｜ 平台：Windows 10/11（x64）｜ 技术栈：Go + Wails v2 + 原生 Vanilla JS

---

## 1. 项目概述

**Auto Dark Mode** 是一个轻量级的 Windows 桌面工具，根据时间自动把系统在 **深色 / 浅色模式** 之间切换：

- 支持 **固定时间** 计划，或 **按经纬度计算的日出/日落** 计划；
- 通过改写 Windows 主题注册表并广播设置变更，让**系统级界面（任务栏、开始菜单、资源管理器）和所有应用**同步切换；
- 提供系统托盘图标、设置界面、中英文双语、开机自启、关闭收起到托盘等完整配套。

**运行时依赖**：WebView2 运行时（Win10/11 自带）。**硬件依赖**：无（GPS 定位为尽力而为，可回退 IP / 手动 / 城市）。

## 3. 功能说明

### 3.1 自动切换模式

- **日出/日落模式（默认）**：用 NOAA 太阳算法根据经纬度计算每日日出、日落时间，`日出→浅色`、`日落→深色`。算法已用纽约市真实坐标的已知日出日落值做过单元测试校验（误差 < 15 分钟）。
- **固定时间模式**：用户设定“深色从…”“浅色从…”，支持跨午夜（如 19:00–07:00）。
- **调度循环**：每 30 秒检查一次当前时间所处的模式并应用，因此休眠唤醒后最多半分钟内纠正。

### 3.2 系统级深浅色切换机制

切换时写入注册表：

```
HKCU\Software\Microsoft\Windows\CurrentVersion\Themes\Personalize
  AppsUseLightTheme    0=深色 1=浅色
  SystemUsesLightTheme 0=深色 1=浅色
  SystemUseLightTheme  保持一致（部分 Windows 构建会读取此变体键）
```

随后按经典顺序 调用 uxtheme.dll 的 `RefreshImmersiveColorPolicyState()` → 广播 `WM_SETTINGCHANGE`（参数 `ImmersiveColorSet`）通知 Shell 重绘，再对任务栏窗口定向投递。**关键经验**：
- 仅写注册表不足以让任务栏/开始菜单重绘，必须广播；
- `SendMessageTimeout(HWND_BROADCAST)` 是同步的，可能阻塞数秒，因此**所有广播都在后台 goroutine 执行**，绝不占用 UI/托盘线程；
- `SendMessageTimeout` 带 `SMTO_ABORTIFHUNG` 时对**挂起窗口静默丢弃**消息——唤醒早期挂起的任务栏会因此错过跳变广播且无从补发，所以对任务栏窗口额外补一条**排队式 `PostMessage`**（lParam 指向进程级永久 UTF-16 缓冲），挂起窗口恢复泵消息后仍能收到；
- **单次广播毫秒级生效**，但**每次主题切换都会自带 2/5/10/20/40 秒的“愈合长尾”补发**，并开启随后 3 分钟的调度周期重播窗口——Shell 若正忙（如刚从休眠恢复）而错过首条广播，稍后空闲即可补上；任务栏与资源管理器文件列表区域都只在收到此类通知后才重绘，多轮重发不依赖任何唤醒探测；
- **Shell 只对“注册表值真实变化”的广播重绘**：实测（深色时段睡眠 → 浅色时段唤醒）发现，唤醒后任务栏/资源管理器内容区会残留旧主题，此时“值不变”的重复广播一律被忽略，只有让注册表经历一次真实的 深↔浅 翻转才能让 Shell 缓存重新同步——因此当注册表已等于目标主题时，改用**翻转式愈合**（见下）而非单纯补发；
- 任务栏/开始菜单跟随 `SystemUsesLightTheme`，应用跟随 `AppsUseLightTheme`，唤醒早期 Shell 未就绪时任务栏最容易错过广播，因此**唤醒愈合不依赖单一事件通道**：托盘窗口处理 `WM_POWERBROADCAST` 全部唤醒代码（含现代待机的 Away-Mode 电源设置通知的**唤醒方向**——入睡方向不触发任何动作，否则其武装的延迟定时器会在睡眠中“到期”、唤醒瞬间触发，架空整个延迟设计），调度循环还会用 `QueryUnbiasedInterruptTime` 与墙钟的差值独立探测“刚唤醒”。

**唤醒探测的正确计数器（决定性教训）**：`GetTickCount64` 的计数是**有偏的（biased），包含睡眠/休眠时间**（MSDN 明确记载；不含睡眠的是 `QueryUnbiasedInterruptTime`）。曾用 `GetTickCount64` 做差值探测并假设它睡眠期间不走——结果是探测**从未触发**，唤醒后第一个调度 tick 走普通路径立即写主题+广播，Shell 未就绪错过广播，任务栏永久卡死；之前几轮“延迟应用”修复全部因此被架空。现用无偏计数器对比墙钟（差值 > 30 秒即判定睡过）。

**翻转式愈合（flip heal）**

托盘”强制深色 / 强制浅色 / 自动”在注册表已匹配目标主题时（`applyThemeHealed` 判定）执行 `flipHealTheme`，以及唤醒兜底路径（见下）也会触发它：

1. 写入**相反**的**系统侧**主题值（仅 `SystemUsesLightTheme` / `SystemUseLightTheme`，不动 `AppsUseLightTheme`）——失步的只会是任务栏侧，只翻它可让**所有应用不闪屏**；
2. 调用 `RefreshImmersiveColorPolicyState()` → **同步**广播 `ImmersiveColorSet` → 定向投递任务栏；
3. **等待 3 秒**（`flipHealPause`，按实际运行时间计——中途入睡则唤醒后补足剩余，避免注册表在相反值上“停摆”整晚）——Shell 对注册表跳变的响应有滞后，两次相反跳变挨得太近时第二跳会被丢失（任务栏停在相反主题），3 秒与手动”先深后浅”有效时的节奏一致；
4. 写回**目标**主题值（全键）→ 再次刷新+广播；
5. 对任务栏窗口（主任务栏 + 副显示器任务栏，EnumWindows 枚举）**定向补发** `WM_SETTINGCHANGE` + `WM_THEMECHANGED` + 排队式 `PostMessage`（多路径送达）；
6. 启动广播长尾兜底。

整个流程在独立 goroutine 上执行（两次同步广播各可能阻塞数秒）。并发请求**合并**：进行中的翻转只保留一个排队请求，且仅当其目标与刚完成的翻转不同才重跑。**翻转进行中调度器暂停写入主题**（`flipActive()` 检查），避免与翻转的中间值打架。

**翻转的触发策略（重要教训的修正版）**：早期版本在自动路径上做**全键**自动翻转——健康 Shell 也会被拉着闪一整轮屏，且曾因重复触发把刚治好的任务栏再次打回深色，遂一度改为“自动路径零翻转”。但唤醒场景下任务栏可能卡死且“值不变”的广播救不了它，只有真实翻转型治愈有效。现版本折中：翻转只翻**系统侧键**（应用永不闪屏），且自动翻转**只在“唤醒后的延迟应用发生了真实跳变”时执行一次**（约唤醒后 45 秒，与实测手动矫正生效的时机一致；若期间用户覆盖了主题或调度已变则取消）。执行前**先采样任务栏真实像素**（`taskbarpix.go`：BitBlt 9×3 网格取亮度中位数；`GetPixel` 在新 Windows 构建已不再导出，且 LazyProc 缺过程会 panic，故所有采样 API 先 `Find()` 探测、失败即降级）：读数高置信度已是目标色则**跳过翻转（零闪动）**，只补投递；读数模糊或采样不可用一律退回翻转——**未知状态永不当作“无需处理”**。

**唤醒后延迟应用（自动路径的根治方案）**

失步状态的成因是”真实注册表跳变的广播在 Shell 未就绪时发出”。因此（`scheduleWakeApply`）：

- 唤醒后（调度探测 / 托盘电源事件，两路去重）**头 8 秒不写注册表**（`wakeApplyDelay`，等待按实际运行时间计，防睡眠穿透）；
- **待决期间调度 tick 一律让行**：Go 的 ticker 在睡眠期间错过的 deadline 会在唤醒瞬间背靠背连发——第一个 tick 走延迟路径，紧随其后的第二个 tick 墙钟差极小、会被合法判为“未睡眠”而走普通应用路径（唤醒 +0.5 秒偷跑写入：偷走真实跳变、架空 8 秒延迟、连带解除 45 秒安全网——2026-09 由诊断日志实锤的根因）。故唤醒应用待决期间所有 `tick` 直接让行（日志记 `tick: deferred`）；
- Shell 就绪后一次性应用目标主题：跨睡眠的主题变化是唤醒后唯一一次真实跳变，落在能听到广播的 Shell 上，任务栏跟着重绘——**失步状态根本不会形成**；主题未变化时该次应用是同值写入 + 广播，无害；
- 唤醒期间的其他信号不推迟这次应用（先到先得），应用时若用户翻转正在进行则跳过（下一个调度周期兜底）；
- 若该次应用是**真实跳变**，再调度一次 45 秒后的**任务栏侧兜底愈合**（`scheduleStuckHeal`）：执行前先经**像素门禁**采样任务栏真实读数（见上“翻转的触发策略”）——读数高置信度已是目标色则**跳过翻转（零闪动）**、只补投递；读数模糊或确实卡住才执行翻转（仅系统侧键）。翻转后有 **+2s/+5s 投递阶梯**重发定向通知（保证“翻回”必达），愈合窗口结束时另有一次**最终定向戳**封住“恢复悬崖”（此前窗口一关、注册表又一致，未重绘的 Shell 将永久卡死）。

### 3.3 位置获取（自动定位）

按优先级链衰减，任一步失败自动进入下一步：

1. **GPS**：通过 PowerShell（`CREATE_NO_WINDOW` 隐藏窗口）调用 Windows Location API——先 `Geolocator::RequestAccessAsync()`（静态方法）向系统**申请定位权限**（首次会触发系统授权），允许后再 `GetGeopositionAsync()` 取坐标；
2. **IP 推算**：`ip-api.com` 失败后自动回退 `ipinfo.io`（HTTP/HTTPS 各一）；
3. 全部失败：明确提示“无法获取当前位置，请手动设置。”（中英文跟随语言）。

另有**手动经纬度**和**城市选择器**（约 190 个城市，中英文名，可搜索过滤），不需要网络即可使用。

**自动解析绝不在主循环上同步执行**（2026-09-23 教训）：GPS+IP 探测链最坏需数十秒，而 `currentLocation` 持应用互斥锁、又会被启动 tick 在 Wails 主循环上调用——同步解析会同时饿死页面资源（AssetServer）与全部绑定调用，表现为**安装后首次打开黑窗卡死 ~30 秒、点击无响应**。现行方案：自动结果持久化在 `location_cache.json`，启动秒读磁盘缓存；解析（冷启动 / 失败重试 / 缓存过期刷新）全部在后台 goroutine 完成，**刷新失败保留旧坐标**只顺延下次重试；启动首 tick 也改为异步执行。

**定位的节流与坐标防护（2026-09-24）**：成功缓存 **6 小时**才后台刷新（首版误用 10 分钟 → 24/7 每 10.5 分钟一次 GPS 子进程、一天 63 次），失败仍 10 分钟重试；`app.log` 每次解析记录坐标。单次坐标跳变 **>2°（约 200km）拒收**并保留旧坐标、10 分钟后再探，**连续两次互相一致才采纳**（旅行场景）——防实测出现过的坏 fix：Windows Location 曾回传**西偏约 10°（约 1000km）**的坐标并存活 2 小时 26 分，把日落边界挪了 50 分钟（当次因机器恰好睡眠而零伤害；solar 算法本身经临时复现测试验证无误）。

### 3.4 系统托盘

- 原生 Win32 托盘（`Shell_NotifyIcon`），**右键/左键均可弹出菜单**，菜单项：
  - **已启用**（勾选开关，点击即切换自动启用状态）
  - 打开设置
  - 强制深色 / 强制浅色 / 自动（即使已是该模式也会强制重算一次，可用来“矫正”残留）
  - 退出
- **托盘图标随主题变化**：深色模式显示月亮、浅色模式显示太阳；应用切主题时主动推送更新图标，另有定时兜底与周期重发，防 Shell 缓存旧图标。
- 托盘线程通过 `runtime.LockOSThread()` 固定，避免 Go goroutine 迁移导致 Win32 消息循环失效。

### 3.5 设置界面

按“保存模型”分成两组，避免认知混乱：

- **计划与位置设置**（需要点击“保存计划与位置设置”按钮才生效）：模式、固定时间、位置来源、经纬度、城市。按钮位于该圆角分组块右下角，保存中显示“保存中…”，成功后短暂显示“已保存 ✓”。
- **立即生效区**（改动即生效，无需保存）：顶部启用开关、手动主题（自动/深色/浅色）、语言、开机自启、关闭时最小化到托盘。

附加特性：
- **界面跟随系统主题**：设置窗口自身随系统深浅色即时切换（基于 `prefers-color-scheme` 同步、即时）。
- **中英文双语**：界面、托盘菜单、状态提示全程双语；默认跟随系统语言（`GetUserDefaultUILanguage`），可在设置中手动覆盖为 English / 中文。

### 3.6 生命周期与可靠性

- **单实例**：命名互斥量防重复启动（含短暂重试，误拦概率低）。
- **关闭收起到托盘**（默认开启）：点窗口 X 最小化到托盘；托盘“退出”才真正退出（`forceExit` 绕过收起逻辑）。
- **开机自启**：写 `HKCU\...\CurrentVersion\Run\AutoDarkMode`；**每次启动自动重写 Run 键**指向当前 exe 路径（exe 移动/重建后仍有效）；关闭自启时顺带清理残留。
- **休眠唤醒愈合（多路探测，去重）**：① 托盘窗口处理 `WM_POWERBROADCAST` 的全部 PBT_APMRESUME* 唤醒事件，并注册 `GUID_SYSTEM_AWAYMODE` 电源设置通知的**唤醒方向**（入睡方向不触发——否则其武装的延迟定时器会在睡眠中“到期”、唤醒瞬间触发，架空延迟设计），覆盖现代待机（S0 低功耗空闲，不发送唤醒事件）的唤醒；② 调度循环用 `QueryUnbiasedInterruptTime`（无偏中断时间，不含睡眠/休眠）相对墙钟的差值独立探测唤醒（差值 > 30 秒即判定睡过；曾误用有偏的 `GetTickCount64` 导致探测从未生效——见 3.2 的教训）。任一通道触发即：**头 8 秒不写主题注册表**（等待按实际运行时间计），随后一次性延迟应用目标主题（Shell 已就绪，真实跳变的广播不会被错过——失步状态不会形成；两路信号去重合并为一次应用），并在唤醒后 3 分钟内让调度循环即使主题已匹配也周期重广播；若该次应用是真实跳变，45 秒后另有一次性任务栏侧兜底翻转。**此外每次真实主题切换都会自带长尾 + 3 分钟周期重播窗口**。若极端情况下兜底翻转也失手，托盘单击"强制深/浅"即触发翻转式愈合矫正（见 3.2）。
- **启动日志**：`%APPDATA%\AutoDarkMode\startup.log` 记录每次启动/被拦/退出，方便排查开机自启。
- **诊断日志**：`%APPDATA%\AutoDarkMode\app.log`（1MB×3 轮转，毫秒时间戳）记录唤醒探测、注册表写入（含写后快照）、广播/定向投递、翻转与门禁决策、像素采样亮度——唤醒与主题链路全程可观测（2026-09 的根因分析即靠它完成）。**排查手册（事件目录 / 健康唤醒基准时间线 / 病态签名速查 / Playbook / 常量与代码位置）见 [`LOGGING.md`](LOGGING.md)。**

## 4. 使用说明

### 4.1 安装与运行

- **便携版**：直接运行 `autodark.exe`。
- **安装版**：运行 `autodark-amd64-installer.exe` 按向导安装（可选 English / 简体中文界面；写入 Program Files、创建开始菜单与桌面快捷方式、安装卸载程序，完成页可选“运行”；安装前检测运行中的实例并可选择结束进程继续）。

### 4.2 快速上手

1. 启动后默认开启自动模式（日出/日落 + 自动定位）；
2. 若自动定位不可用：设置 → 位置 → 选择“城市”或勾选“进入坐标”，点“保存计划与位置设置”；
3. 想固定时段：设置 → 计划 → 选“固定时间”，设定深浅色时段，点保存；
4. 右上开关控制是否启用自动切换；需要即时改主题时使用“立即生效区”的深/浅按钮或托盘菜单。

### 4.3 托盘菜单说明

| 菜单项 | 作用 |
|---|---|
| 已启用（☑） | 勾/去勾 启用或停用自动切换 |
| 打开设置 | 显示设置窗口 |
| 强制深色 / 强制浅色 | 立即切换；若注册表已是该主题（如唤醒后残留），自动执行翻转式愈合矫正（只翻系统侧键，应用不闪屏） |
| 自动 | 回到自动计算模式并立即重算应用一次 |
| 退出 | 彻底退出并清理托盘 |

### 4.4 常见问题

- **切换后任务栏没变**：点一次托盘“强制浅色/深色”即可当场矫正——注册表已匹配时会自动执行翻转式愈合（只翻系统侧键的深↔浅往返，强迫 Shell 缓存重同步，应用不闪屏），不再需要手动“先深后浅”两步；自动模式下每次切换自带补发广播与 3 分钟周期重播，跨主题唤醒后另有唤醒 8 秒的延迟应用与 45 秒的一次性任务栏侧兜底翻转。
- **自动定位失败**：按提示改用城市/手动坐标；GPS 首次会弹系统权限询问。
- **开机不自动启动**：确认设置里“开机自启”已开；重启后查看 `%APPDATA%\AutoDarkMode\startup.log`（有 `booting…startup ok` 即正常拉起）。

## 7. 构建与发布

发布形式（命令均在 `autodark/` 目录下执行）：

```bash
# 便携版单 exe → build/bin/autodark.exe
wails build

# NSIS 引导安装包 → build/bin/autodark-amd64-installer.exe
wails build -nsis

# 或一键构建：全部 / 仅便携 / 仅安装包
build.bat
build.bat portable
build.bat installer
```

- **版本迭代**：SemVer；产出新 exe 前运行 `build\bump-version.ps1 -Patch|-Minor|-Major` 同步全部版本位置（真源 `version.go` → exe 属性 / NSIS / 日志 / 文档；升位规则与版本历史见 [VERSIONING.md](VERSIONING.md)）。
- **exe 版本资源的坑（最终修复，走 wails 原生单 syso）**：wails 用 tc-hib/winres 把 icon+manifest+`build/windows/info.json` 版本编成单个 `<项目名>-res.syso`（构建后自动清理）。版本会**静默丢失**的真因在 info.json 的 `info` **键格式**：winres 用 `Sscanf("%X", uint16)` 解析该键——**必须是 4 位短 LCID（`"0409"` / `"0000"`）**；写成 goversioninfo 风格的 8 位 `"040904B0"` 会越界报错、语言表被整段丢弃（exe 内直接没有 `VS_VERSION_INFO`）；而历史默认 `"0000"`（LangNeutral）在 .NET 的文件属性里读为空白。现行 info.json：`"0409"` 键 + 4 段 fixed（`{{.Info.ProductVersion}}.0` 模板，随 wails.json 每次构建自动渲染）+ `FileVersion`/`ProductVersion` 字符串——右键属性正常显示。⚠️ 不要再往仓库根放第二个 syso（会报 `too many .rsrc sections` 链接失败）。
- **新增 App 绑定方法的坑**：wails v2.15 的 "Generating bindings" 步骤可能报 `Done` 却**不更新** `frontend/wailsjs/go/main/App.js` / `.d.ts`（实测文件 mtime 纹丝不动）。新增方法后若 vite 报 `"X" is not exported by "wailsjs/go/main/App.js"`，按邻近函数的同格式手动补一行 wrapper 即可——运行时 `window.go.main.App.X` 按方法名反射解析，与自动生成等效。
- NSIS 需安装（`scoop install nsis`，提供 `makensis`）。
- 开发热重载：`wails dev`。
- 安装包向导：欢迎 → 安装目录 → 安装 → 完成（可选立即运行）；创建开始菜单/桌面快捷方式、检查 WebView2、带卸载程序。
- **双语安装界面（English / 简体中文）**：安装启动时弹出语言选择对话框（`MUI_LANGDLL_ALWAYSSHOW` 保证**每次运行都弹出**，重新安装也不例外；选择写入 `HKCU\Software\AutoDarkMode` 供卸载程序沿用语言），向导各页与提示均随所选语言显示；完成页“运行”复选框文本也随语言本地化。
- **安装时结束运行中的实例**：复制文件前用 `tasklist /FI "IMAGENAME eq …" | find` 检测进程是否存活（`find` 退出码 0 = 存活），存活则弹出提示——点击“确定”用 `taskkill /F /T` 结束进程并继续安装，点击“取消”退出安装程序；静默安装（/S）不询问直接结束；检测循环直到进程消失（防止结束失败或应用自启）。卸载程序同样先静默结束进程再删除文件。
- **project.nsi 必须保存为 UTF-8 带 BOM**：脚本含中文文本，makensis 只有在检测到 BOM 时才按 UTF-8 解析，否则报 `Bad text encoding`。

## 8. 关键设计决策备忘

1. **主题切换 = 注册表 + 广播**；广播必须异步、平时一次、仅启动/唤醒用长尾。**Shell 只对真实变化的广播重绘**：注册表已匹配时改用翻转式愈合（`applyThemeHealed` → `flipHealTheme`），不做无效的重复广播。
2. **GPS 用 PowerShell 但隐藏窗口**（`CREATE_NO_WINDOW`），权限请求用静态 `RequestAccessAsync`。
3. **托盘自绘 Win32 而非第三方库**：配合 `LockOSThread` 解决 Go 与 Win32 消息循环的线程亲和问题。
4. **托盘图标随主题**：深=月亮/浅=太阳，应用侧推送 + 轮询兜底 + 周期重发。
5. **单实例 + 启动重写 Run 键 + 启动日志**：保证开机自启稳定、可排查。
6. **界面主题跟随系统**：`prefers-color-scheme` 同步，启动无深/浅闪变。
7. **唤醒愈合多路去重 + 兜底**：每次真实主题切换自带广播长尾（2/5/10/20/40 秒，**按实际运行时间计——防睡眠穿透**）+ 3 分钟周期重播窗口（每次重播配**定向戳**，其 `PostMessage` 能触达挂起的任务栏）；另外 `WM_POWERBROADCAST` 全部唤醒代码、Away-Mode 电源设置通知的唤醒方向（现代待机）、调度循环 `QueryUnbiasedInterruptTime` 差值探测三路去重后会在 Shell 就绪后（唤醒 +8 秒）一次性延迟应用目标主题，真实跳变的广播必然落在就绪的 Shell 上；**唤醒应用待决期间调度 tick 一律让行**（Go ticker 移压 deadline 唤醒后连发，第二个 tick 曾在唤醒 +0.5 秒偷跑写入——2026-09 实锤根因）。若该次应用是真实跳变，45 秒后还有一次**经像素门禁**的仅翻系统侧键兜底（门禁判定已正确则跳过翻转=零闪动；应用永不闪屏），翻转后有 +2s/+5s 投递阶梯，愈合窗口结束时补**最终定向戳**封“恢复悬崖”。唤醒探测必须用**无偏**计数器（`GetTickCount64` 有偏、含睡眠时间，曾使整套延迟设计被架空）。全程由 `app.log` 诊断日志记录（1MB×3 轮转）。**1.3.0 起**真实切换（唤醒应用或调度切换）后另启**视觉看门狗**（`watchdog.go`）：+45s/+2m 无注册表补戳、+1m/+3m/+8m/+15m 任务栏像素采样——**仅高置信失配才执行翻转愈合**（正确或读数模糊只补戳，绝不误闪），把"3 分钟愈合窗口关闭后外壳复发失步、无人能救"的残余洞封死：任何复发最迟 15 分钟内自动治愈、永不需手动（2026-09-24 实测复发一次即此类）。

## 9. 已知限制与注意事项

- **GPS 定位**依赖系统位置权限与设备；未授权或无设备时自动回退 IP，离线时回退失败会提示手动设置。
- **IP 定位**需要网络，且返回的是运营商出口的近似位置（通常够用于日出日落）。
- **城市表**为内置静态数据（约 190 个主要城市，中文名 + 英文规范键）。
- 手动坐标为 0,0 时表示“未设置”，日出日落计算将基于赤道经度零经线，可能不符合预期——请勿留空使用。
- 若任务栏在极少数情况下仍残留旧主题，托盘“强制深色/浅色”单击即可通过翻转式愈合矫正（会有一次约 3 秒的深↔浅往返）。
